# 비게임 출시 체크리스트

## 점검 기준과 범위

- 점검일: 2026-11-03 (한국 시간). 코드 기준: `9fbd57a`, SDK `@apps-in-toss/web-framework` 3.9.0.
- 대상 명세: `openspec/changes/add-project-pathfinder-mvp`, task 6.4.
- 정본: [비게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-nongame.md), [사용자 식별키 발급](https://developers-apps-in-toss.toss.im/guide/authentication/anon-key.md), [User.getAnonymousKey](https://developers-apps-in-toss.toss.im/documentation/sdk/domains-api/user/user.getanonymouskey). 당일 docs MCP `getPage`로 본문을 읽었다. 아래 항목은 원문의 순서를 따라 짧게 정리했다.
- **충족**: 명시한 코드·정적 검사 또는 실제 수행한 검증 범위에서 확인했다. 토스앱 동작까지 확인했다는 뜻은 아니다.
- **미충족**: 필요한 구현이 현재 코드에 없다.
- **미검증**: 코드가 있어도 실기기·콘솔·성능 측정 등 필요한 증거가 없다.
- **해당 없음**: 현재 제공하지 않는 선택 기능이다. 기능을 도입하면 다시 점검한다.
- 콘솔 등록·메타데이터·검수·출시 상태는 이번 문서 작업에서 조회하거나 변경하지 않았다. `appName: project-pathfinder`는 개발 중 임시 값이며 실제 등록값과의 일치는 미확인이다.
- 판정 합계: 78개 항목 중 충족 16개, 미충족 0개, 미검증 21개, 해당 없음 41개. 이 합계는 아래 78개 개별 행을 집계한 값이다.

## 미충족과 출시 전 남은 확인

1. **U01 사용자 식별키는 구현했으나 실기기 미검증.** 앱 시작 시 `User.getAnonymousKey()`를 호출해 저장하며, 실패 결과 `"ERROR" | undefined`와 예외는 저장하지 않고 앱 시작도 막지 않는다. 샌드박스는 mock을 반환하므로 토스앱 QR 테스트가 필요하다.
2. **실기기 확인:** QR로 Android 토스앱 진입, SDK 저장 후 완전 종료·복원, 네이티브 바/더보기/닫기/시스템 뒤로가기, 최초 화면 종료, 핀치 제한, 다크 설정의 라이트 표시, 오프라인 핵심 기능, 2초 반응·네트워크·메모리 측정이 남아 있다. SDK mock 또는 메모리 어댑터의 성공을 실제 기기 성공으로 올리지 않았다.
3. **iOS 미검증:** 별도 기기 증거가 없다. 특히 핀치 제한·네이티브 뒤로가기·저장 복원·레이아웃을 확인해야 한다.
4. **콘솔 미검증:** 앱 등록 여부, 실제 `appName`, 국문 이름·로고, 앱 내 기능 소개·스킴을 확인해야 한다. 로컬 `.ait` 생성과 콘솔 업로드·컴파일·검수·출시는 각각 별도 상태다. 이번 작업에서는 업로드·심사 제출·출시를 수행하지 않았다.
5. **식별키와 로컬 데이터의 차이:** 공식 문서상 식별키는 앱 삭제·기기 변경 후에도 같은 사용자에게 동일하지만, 이것이 로컬 프로젝트 데이터를 복구하거나 동기화한다는 뜻은 아니다. 홈의 데이터 보존 안내를 유지하고 계정 변경 시 데이터 구분 정책도 검토해야 한다. 실제 식별키는 샌드박스 mock이 아닌 토스앱 QR 테스트가 필요하다.

이 문서는 task 6.4의 대조 기록이다. 위 미검증 항목이 남아 있어 출시 가능 또는 전체 통합·실기기 검증 완료로 판정하지 않는다.
