# Spec Delta

## Purpose

작업 사이의 선후 관계를 같은 프로젝트 안의 방향성 비순환 그래프로 유지하여, 이후의 판정과 일정 계산이 항상 유효한 입력을 받도록 보장한다.

## ADDED Requirements

### Requirement: 다중 선행 작업 지정
The system SHALL 작업마다 같은 프로젝트의 다른 작업을 0개 이상 선행 작업으로 지정하고 변경할 수 있게 한다.

#### Scenario: 두 작업을 기다리는 작업
- **WHEN** 사용자가 "통합 테스트"의 선행 작업으로 "UI 제작"과 "API 개발"을 선택하고 저장한다
- **THEN** "통합 테스트"는 두 작업 모두를 선행 작업으로 갖는다

### Requirement: 자기 참조 차단
The system MUST 작업이 자기 자신을 선행 작업으로 갖지 못하게 한다.

#### Scenario: 선택지에서 제외
- **WHEN** 사용자가 기존 작업의 선행 작업 선택지를 연다
- **THEN** 편집 중인 작업은 선택지에 나타나지 않는다

### Requirement: 순환 참조 차단
The system MUST 저장 결과가 순환을 만드는 선행 작업 변경을 거부하고, 기존 관계를 유지한 채 순환을 만드는 작업을 안내한다.

#### Scenario: 간접 순환
- **WHEN** A가 B의 선행 작업이고 B가 C의 선행 작업일 때 사용자가 C를 A의 선행 작업으로 저장한다
- **THEN** 저장이 거부되고 기존 관계가 유지되며 순환 경로의 작업들이 안내된다

### Requirement: 프로젝트 간 연결 차단
The system MUST 다른 프로젝트의 작업을 선행 작업으로 저장하지 않는다.

#### Scenario: 선택지 범위
- **WHEN** 사용자가 선행 작업 선택지를 연다
- **THEN** 현재 프로젝트의 작업만 나타난다

### Requirement: 작업 삭제 시 참조 정리
The system SHALL 작업을 삭제할 때 그 작업을 가리키는 다른 작업의 선행 작업 참조를 함께 제거하고, 삭제 확인 단계에서 영향을 받는 후속 작업을 알린다.

#### Scenario: 중간 작업 삭제
- **WHEN** A → B → C 관계에서 사용자가 B를 삭제한다
- **THEN** C의 선행 작업에서 B가 제거되고, C는 A를 선행 작업으로 자동 상속하지 않는다

### Requirement: 관계 변경 후 재계산
The system SHALL 의존 관계가 바뀌면 시작 가능 여부, 일정 분석, 경로도를 같은 데이터로 즉시 다시 계산한다.

#### Scenario: 선행 작업 추가
- **WHEN** 시작 가능한 작업에 완료되지 않은 선행 작업을 추가하고 저장한다
- **THEN** 해당 작업이 대기 중으로 바뀌고 목록, 경로도, 일정 분석에 같은 결과가 반영된다
