# Spec Delta

## Purpose

저장된 작업 상태와 선행 작업 완료 여부로부터 지금 시작할 수 있는 작업과 막힌 이유를 판정해, 사용자가 다음 행동을 바로 알 수 있게 한다.

## ADDED Requirements

### Requirement: 표시 상태 판정
The system SHALL 작업마다 표시 상태를 하나로 판정한다. 저장 상태가 완료면 완료, 진행 중이면 진행 중이다. 시작 전이면 선행 작업이 없거나 모두 완료일 때 시작 가능, 그 외에는 대기 중이다. 표시 상태는 저장하지 않고 항상 계산한다.

#### Scenario: 선행 작업이 없는 작업
- **WHEN** 선행 작업이 없는 시작 전 작업을 본다
- **THEN** 시작 가능으로 표시된다

#### Scenario: 일부 선행 작업만 완료
- **WHEN** 선행 작업 두 개 중 하나만 완료된 시작 전 작업을 본다
- **THEN** 대기 중으로 표시된다

#### Scenario: 선행 작업 완료로 전환
- **WHEN** "UI 제작"과 "API 개발"을 모두 완료한다
- **THEN** 두 작업을 기다리던 "통합 테스트"가 시작 가능으로 바뀐다

### Requirement: 대기 사유 표시
The system SHALL 대기 중인 작업에 완료되지 않은 선행 작업의 이름을 모두 표시한다.

#### Scenario: 남은 선행 작업 안내
- **WHEN** "API 개발"만 완료되지 않아 대기 중인 "통합 테스트"를 본다
- **THEN** "API 개발"이 완료되어야 한다는 사유가 표시된다

### Requirement: 선행 작업 미완료 경고
The system SHALL 선행 작업이 미완료인데 진행 중이거나 완료 상태인 작업에 완료되지 않은 선행 작업을 경고로 표시하되, 저장 상태와 표시 상태는 유지한다.

#### Scenario: 선행 작업의 완료 취소 후
- **WHEN** 선행 작업의 완료가 취소된 뒤 진행 중인 후속 작업을 본다
- **THEN** 후속 작업은 진행 중으로 표시되고 미완료 선행 작업 경고가 함께 표시된다

### Requirement: 다음 할 일 우선 표시
The system SHALL 프로젝트 상세의 첫 영역에 진행 중 작업과 시작 가능 작업을 먼저 보여주고, 그 아래에 대기 중 작업과 사유, 전체 작업 목록을 보여준다.

#### Scenario: 프로젝트 상세 진입
- **WHEN** 시작 가능한 작업이 있는 프로젝트의 상세 화면을 연다
- **THEN** 스크롤 없이 첫 영역에서 시작 가능한 작업을 볼 수 있다

#### Scenario: 시작할 작업이 없음
- **WHEN** 모든 작업이 완료된 프로젝트의 상세 화면을 연다
- **THEN** 다음 할 일 영역에 프로젝트의 작업을 모두 마쳤다는 안내가 표시된다

### Requirement: 색상 외 상태 구분
The system SHALL 모든 표시 상태를 색상만이 아니라 텍스트로도 구분한다.

#### Scenario: 상태 라벨
- **WHEN** 목록이나 경로도에서 작업을 본다
- **THEN** 완료, 진행 중, 시작 가능, 대기 중 중 하나가 글자로 표시된다
