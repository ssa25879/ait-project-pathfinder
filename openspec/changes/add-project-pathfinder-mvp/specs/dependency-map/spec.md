# Spec Delta

## Purpose

사용자가 직접 그리지 않아도 작업 흐름을 경로도로 확인하고, 좁은 모바일 화면에서도 선택한 작업의 앞뒤 관계를 읽을 수 있게 한다.

## ADDED Requirements

### Requirement: 자동 배치 경로도
The system SHALL 프로젝트의 작업을 노드로, 선행 → 후속 관계를 방향이 보이는 연결선으로 자동 배치한다. 선행 작업은 항상 후속 작업보다 위쪽 단계에 놓는다. 사용자가 노드나 연결선을 직접 그릴 필요는 없다.

#### Scenario: 대표 시나리오 배치
- **WHEN** "기획" 뒤에 "UI 제작"과 "API 개발"이 이어지고 "통합 테스트"가 두 작업을 기다린다
- **THEN** "기획", 두 작업, "통합 테스트" 순서의 세 단계로 배치되고 방향이 보이는 연결선 4개가 표시된다

#### Scenario: 작업이 없는 프로젝트
- **WHEN** 작업이 없는 프로젝트의 경로도를 연다
- **THEN** 오류 없이 작업을 추가하라는 빈 상태 안내가 표시된다

### Requirement: 스크롤 탐색
The system SHALL 경로도가 화면보다 크면 세로·가로 스크롤로 전체를 볼 수 있게 하고, 작업이 15개인 프로젝트에서도 작업명을 읽을 수 있는 크기를 유지한다. 제스처 확대·축소는 제공하지 않는다.

#### Scenario: 넓은 단계
- **WHEN** 한 단계의 노드 폭 합계가 화면 폭을 넘는다
- **THEN** 노드를 줄이는 대신 스크롤로 나머지 노드를 볼 수 있다

### Requirement: 상태와 핵심 경로 표시
The system SHALL 각 노드에 작업명과 표시 상태를 글자로 표시하고, 핵심 작업과 핵심 연결을 색상 외의 구분(라벨, 선 굵기 등)으로 강조한다. 표시 값은 목록·일정 분석과 같은 계산 결과를 사용한다.

#### Scenario: 화면 간 일관성
- **WHEN** 목록에서 시작 가능으로 표시된 핵심 작업을 경로도에서 본다
- **THEN** 노드에 같은 상태와 핵심 작업 표시가 나타난다

### Requirement: 노드 선택과 상세 정보
The system SHALL 노드를 터치하면 작업명, 예상 기간, 표시 상태, 여유 기간, 선행 작업, 후속 작업을 보여주고, 작업 편집으로 이동할 수 있게 한다.

#### Scenario: 노드 선택
- **WHEN** 사용자가 "UI 제작" 노드를 터치한다
- **THEN** 선행 작업 "기획"과 후속 작업 "통합 테스트"를 포함한 상세 정보가 표시된다

### Requirement: 선택 작업 중심 보기
The system SHALL 선택한 작업과 직접 연결된 선행·후속 작업만 보여주는 보기를 제공하고, 표시된 작업을 터치해 기준 작업을 옮기거나 전체 보기로 돌아갈 수 있게 한다.

#### Scenario: 중심 보기 전환
- **WHEN** 사용자가 작업을 선택한 뒤 중심 보기로 전환한다
- **THEN** 해당 작업과 직접 연결된 선행·후속 작업만 표시된다

#### Scenario: 기준 작업 이동
- **WHEN** 중심 보기에서 후속 작업을 터치한다
- **THEN** 그 작업을 기준으로 보기가 바뀐다

#### Scenario: 전체 보기 복귀
- **WHEN** 중심 보기에서 전체 보기를 선택한다
- **THEN** 프로젝트의 모든 작업과 연결선이 다시 표시된다
