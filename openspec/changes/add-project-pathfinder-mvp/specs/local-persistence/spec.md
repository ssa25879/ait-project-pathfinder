# Spec Delta

## Purpose

서버와 로그인 없이 프로젝트와 작업 데이터를 기기에 저장하고 복원하며, 저장 실패와 데이터 보존 조건을 사용자에게 알려 데이터 유실을 줄인다.

## ADDED Requirements

### Requirement: 저장과 복원
The system SHALL 프로젝트와 작업의 원본 데이터를 변경 후 기기에 저장하고, 앱을 다시 실행하면 복원한다. 시작 가능 여부와 일정 값 같은 파생 값은 저장하지 않는다.

#### Scenario: 재실행 후 유지
- **WHEN** 사용자가 작업을 추가하고 미니앱을 완전히 종료한 뒤 다시 연다
- **THEN** 추가한 작업과 상태가 그대로 표시된다

#### Scenario: 최초 실행
- **WHEN** 저장된 데이터가 없는 상태로 처음 실행한다
- **THEN** 오류 없이 프로젝트 홈의 빈 상태가 표시된다

### Requirement: 저장 호출 제어
The system SHALL 짧은 시간의 연속 변경을 묶어 저장하되 마지막 변경을 빠뜨리지 않으며, 저장 실패 시 자동 재시도 횟수와 간격을 제한한다.

#### Scenario: 연속 변경
- **WHEN** 사용자가 1초 안에 작업 상태를 여러 번 변경한다
- **THEN** 변경마다 저장을 호출하지 않고, 마지막 상태가 저장된다

### Requirement: 저장 실패 안내
The system SHALL 저장이 재시도 후에도 실패하면 화면의 변경 내용을 유지한 채 저장되지 않았음을 알리고, 사용자가 다시 시도할 수 있게 한다.

#### Scenario: 저장 실패
- **WHEN** 기기 저장소 쓰기가 계속 실패한다
- **THEN** 저장 실패 안내와 다시 시도 동작이 표시되고, 입력한 내용은 화면에서 사라지지 않는다

### Requirement: 손상되거나 읽을 수 없는 데이터 보호
The system MUST 저장 데이터를 읽지 못하거나 해석·검증에 실패하면 빈 데이터로 덮어쓰지 않고, 오류와 다시 시도 동작을 표시한다.

#### Scenario: 해석할 수 없는 데이터
- **WHEN** 저장된 값이 올바른 데이터 형식이 아니다
- **THEN** 저장된 원본 값이 유지되고 데이터를 불러오지 못했다는 안내가 표시된다

#### Scenario: 일시적 읽기 실패
- **WHEN** 앱 시작 시 저장소 읽기가 실패한 뒤 사용자가 다시 시도하여 성공한다
- **THEN** 기존 데이터가 정상적으로 표시된다

### Requirement: 데이터 버전 관리
The system SHALL 저장 데이터에 형식 버전을 기록하고, 이전 버전은 현재 형식으로 변환해 읽는다. 현재 앱보다 새로운 버전은 변경하지 않고 업데이트 필요 안내를 표시한다.

#### Scenario: 새로운 버전의 데이터
- **WHEN** 저장된 데이터의 버전이 앱이 지원하는 버전보다 높다
- **THEN** 데이터가 덮어써지지 않고 업데이트가 필요하다는 안내가 표시된다

### Requirement: 데이터 보존 조건 안내
The system SHALL 데이터가 이 기기에만 저장되며, 토스 앱을 삭제하거나 미니앱 데이터를 삭제하면 지워질 수 있다는 점을 앱 안에서 안내한다.

#### Scenario: 안내 확인
- **WHEN** 사용자가 프로젝트 홈의 데이터 안내를 연다
- **THEN** 데이터 저장 위치와 삭제되는 조건을 볼 수 있다

### Requirement: 사용자 식별키 확인과 저장
The system SHALL 앱 시작 시 토스 사용자 식별키를 확인해 기기에 저장하되, 값이 달라졌을 때만 쓴다. 식별키를 얻거나 저장하지 못해도 앱 시작과 핵심 기능을 막지 않으며, 식별키를 외부로 보내거나 화면에 표시하지 않는다.

#### Scenario: 식별키 저장
- **WHEN** 앱 시작 시 식별키를 받았고 저장된 값과 다르다
- **THEN** 새 값이 저장된다

#### Scenario: 식별키 확인 실패
- **WHEN** 지원하지 않는 토스앱 버전이거나 식별키 확인이 실패한다
- **THEN** 프로젝트 데이터와 앱 시작에 영향 없이 정상 동작한다
