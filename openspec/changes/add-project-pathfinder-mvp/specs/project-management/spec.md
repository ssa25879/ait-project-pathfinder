# Spec Delta

## Purpose

사용자가 작업 묶음을 프로젝트 단위로 만들고 관리하며, 프로젝트별 진행 상황을 한눈에 확인할 수 있게 한다.

## ADDED Requirements

### Requirement: 프로젝트 생성
The system SHALL 프로젝트명과 시작일을 필수로, 설명을 선택으로 입력받아 프로젝트를 생성한다. 프로젝트명은 앞뒤 공백을 제거한 뒤 1자 이상 50자 이하여야 하고, 시작일은 실제로 존재하는 날짜여야 한다.

#### Scenario: 유효한 입력으로 생성
- **WHEN** 사용자가 프로젝트명 "이사 준비"와 시작일 2026-12-01을 입력하고 저장한다
- **THEN** 프로젝트 홈에 "이사 준비" 프로젝트가 나타난다

#### Scenario: 프로젝트명 누락
- **WHEN** 사용자가 공백만 있는 프로젝트명으로 저장한다
- **THEN** 프로젝트가 생성되지 않고 프로젝트명을 입력하라는 안내가 표시된다

### Requirement: 프로젝트 수정
The system SHALL 프로젝트명, 설명, 시작일의 수정을 허용하며, 수정 시 생성과 같은 입력 검증을 적용한다.

#### Scenario: 시작일 변경
- **WHEN** 사용자가 프로젝트의 시작일을 변경하고 저장한다
- **THEN** 해당 프로젝트에 표시되는 날짜가 새 시작일 기준으로 다시 계산된다

### Requirement: 프로젝트 삭제
The system SHALL 사용자의 확인을 받은 뒤 프로젝트와 그 프로젝트의 모든 작업을 함께 삭제한다.

#### Scenario: 삭제 확인
- **WHEN** 사용자가 작업이 있는 프로젝트의 삭제를 확인한다
- **THEN** 프로젝트와 소속 작업이 모두 사라진다

#### Scenario: 삭제 취소
- **WHEN** 사용자가 삭제 확인 단계에서 취소한다
- **THEN** 프로젝트와 작업이 변경되지 않는다

### Requirement: 프로젝트 진행 현황 집계
The system SHALL 프로젝트별 진행률과 완료·진행 중·시작 가능·대기 중 작업 수를 표시한다. 진행률은 전체 작업 수 대비 완료 작업 수의 백분율이며, 작업이 없으면 0%로 표시한다.

#### Scenario: 진행률 계산
- **WHEN** 작업 4개 중 1개가 완료된 프로젝트를 프로젝트 홈에서 본다
- **THEN** 진행률이 25%로 표시된다

#### Scenario: 작업이 없는 프로젝트
- **WHEN** 작업이 없는 프로젝트를 프로젝트 홈에서 본다
- **THEN** 진행률 0%와 시작 가능 작업 0개가 오류 없이 표시된다
