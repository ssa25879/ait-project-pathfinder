# Spec Delta

## Purpose

사용자가 최소한의 입력으로 프로젝트의 작업을 만들고 수정하며, 시작 전·진행 중·완료 상태를 관리할 수 있게 한다.

## ADDED Requirements

### Requirement: 작업 생성과 수정
The system SHALL 작업명과 예상 기간을 필수로, 설명과 선행 작업을 선택으로 입력받아 작업을 생성·수정한다. 새 작업의 상태는 시작 전이다.

#### Scenario: 필수 값만으로 생성
- **WHEN** 사용자가 작업명 "기획"과 예상 기간 3일만 입력하고 저장한다
- **THEN** 선행 작업이 없고 상태가 시작 전인 작업이 생성된다

### Requirement: 작업 입력 검증
The system SHALL 앞뒤 공백을 제거한 작업명이 1자 이상 50자 이하이고 예상 기간이 1 이상 999 이하의 정수일 때만 저장한다. 그렇지 않으면 저장하지 않고 잘못된 항목을 안내한다.

#### Scenario: 잘못된 예상 기간
- **WHEN** 사용자가 예상 기간에 0, 음수, 소수 또는 빈 값을 입력하고 저장한다
- **THEN** 작업이 저장되지 않고 예상 기간을 고치라는 안내가 표시된다

#### Scenario: 작업명 누락
- **WHEN** 사용자가 공백만 있는 작업명으로 저장한다
- **THEN** 작업이 저장되지 않고 작업명을 입력하라는 안내가 표시된다

### Requirement: 작업 삭제
The system SHALL 사용자의 확인을 받은 뒤 작업을 삭제한다.

#### Scenario: 삭제 확인
- **WHEN** 사용자가 작업 삭제를 확인한다
- **THEN** 작업이 목록과 경로도에서 사라진다

#### Scenario: 삭제 취소
- **WHEN** 사용자가 삭제 확인 단계에서 취소한다
- **THEN** 작업이 변경되지 않는다

### Requirement: 시작 전 작업의 착수 제한
The system SHALL 선행 작업이 모두 완료된 시작 전 작업만 진행 중 또는 완료로 변경할 수 있게 한다. 대기 중인 작업의 변경 시도는 거부하고 완료되지 않은 선행 작업을 안내한다.

#### Scenario: 대기 중 작업의 착수 시도
- **WHEN** 선행 작업 "기획"이 완료되지 않은 작업 "UI 제작"을 진행 중으로 변경하려 한다
- **THEN** 상태가 바뀌지 않고 "기획"이 완료되어야 한다는 안내가 표시된다

#### Scenario: 시작 가능 작업의 착수
- **WHEN** 사용자가 시작 가능한 작업을 진행 중으로 변경한다
- **THEN** 작업 상태가 진행 중으로 저장된다

### Requirement: 착수한 작업의 상태 변경
The system SHALL 진행 중이거나 완료된 작업을 세 가지 상태 중 어느 것으로든 되돌리거나 변경할 수 있게 한다. 이 변경은 다른 작업의 저장된 상태를 자동으로 바꾸지 않는다.

#### Scenario: 완료 취소
- **WHEN** 후속 작업이 이미 진행 중일 때 사용자가 선행 작업의 완료를 시작 전으로 되돌린다
- **THEN** 선행 작업만 시작 전으로 바뀌고 후속 작업은 진행 중을 유지한다
