# Proposal

## Why

일반 할 일 앱은 작업 사이의 선후 관계를 다루지 않아, 지금 시작할 수 있는 작업과 막힌 이유, 일정에 영향을 주는 작업을 사용자가 직접 따져야 한다. 소규모 프로젝트(초기 목표 5~15개 작업)에 맞춰 이를 자동으로 계산해 주는 앱인토스 비게임 미니앱의 MVP를 만든다. 저장소에는 아직 기획서(`프로젝트_경로도_Project_Pathfinder_개발기획서.md`)만 있으며 코드는 없다.

## What Changes

- React + TypeScript + Vite 기반 앱인토스 WebView 미니앱을 새로 구성한다.
- 프로젝트와 작업의 생성·수정·삭제, 작업 상태 변경을 제공한다.
- 다중 선행 작업을 지정하고 자기 참조·순환 참조·다른 프로젝트 참조를 차단한다.
- 시작 가능·대기 중 여부와 대기 사유를 작업 상태와 별개의 파생 값으로 계산한다.
- 예상 총 기간, ES/EF/LS/LF, 여유 기간, 복수 핵심 경로를 계산한다.
- 작업 의존 관계를 자동 배치 경로도로 보여주고, 선택 작업 중심 보기를 제공한다.
- 서버 없이 기기 안에 데이터를 저장·복원하고 저장 실패를 안내한다.
- 앱인토스 비게임 출시 가이드의 내비게이션·뒤로가기·테마·확대 제한을 따른다.

제외 범위는 기획서 5.2와 같다. 팀 협업, 로그인·동기화 서버, 외부 캘린더·푸시, AI 일정 생성, 자원·휴무일 반영, 광고·게임 요소는 포함하지 않는다. 앱인토스 콘솔 등록, 출시 요청, 심사 제출도 이번 변경에 포함하지 않는다.

기획서와 달라지는 점이 하나 있다. 기획서 4장은 경로도의 "확대 검토"를 언급하지만, 공식 출시 가이드는 지도처럼 꼭 필요한 경우를 제외하고 제스처 확대·축소를 비활성화하도록 요구한다. 따라서 핀치 줌을 제공하지 않고 스크롤과 선택 작업 중심 보기로 대신한다.

## Capabilities

### New Capabilities

- `project-management`: 프로젝트 생성·수정·삭제와 프로젝트별 진행률·작업 수 집계
- `task-management`: 작업 생성·수정·삭제, 입력 검증, 상태 변경
- `task-dependencies`: 선행 작업 지정과 자기 참조·순환·교차 프로젝트 차단, 삭제 시 참조 정리
- `task-readiness`: 시작 가능·대기 중 판정, 대기 사유, 다음 할 일 우선 표시
- `schedule-analysis`: 예상 총 기간, CPM 값, 복수 핵심 경로 계산과 재계산, 계산의 한계 안내
- `dependency-map`: 자동 배치 경로도, 상태·핵심 경로 표시, 노드 상세, 선택 작업 중심 보기
- `local-persistence`: 기기 내 저장·복원, 데이터 버전 관리, 저장 실패와 데이터 보존 조건 안내
- `mini-app-shell`: 화면 이동과 뒤로가기, 앱인토스 내비게이션 바, 라이트 테마, 확대 제한, 빈 상태·오류 상태

### Modified Capabilities

없음. `openspec/specs/`에 기존 명세가 없다.

## Impact

- **코드:** 저장소 루트에 앱 전체를 새로 만든다. 기존 코드 변경은 없다.
- **의존성:** `@apps-in-toss/web-framework`, `@toss/tds-mobile`, `@toss/tds-mobile-ait`, `@emotion/react`, React 18, React Router, Vite, TypeScript, Vitest를 추가한다.
- **외부 시스템:** 서버와 네트워크 API를 사용하지 않는다. 토스 앱의 네이티브 `Storage`만 사용한다.
- **외부 작업:** 토스앱 실기기 테스트에는 콘솔의 앱 등록과 `appName`이 필요하다.
